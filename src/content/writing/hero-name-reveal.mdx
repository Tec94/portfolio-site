The first thing I ever coded was a tank game in Scratch, back in middle school. I spent something like five hours erasing the background off one sprite by hand, because I didn't know there was a faster way. Then I did it again for the next sprite. I still like that part of building, where you keep messing with a small detail until it finally feels right.

This post is about one of those details. When you land on my homepage, my name starts out in the same dark ink as the rest of the heading, and then it turns red from left to right. It takes 700 milliseconds. It's one keyframe, a second copy of my name, and two media queries, and I want to walk through each of them because there's more going on than it looks like.

## The red name comes first

The first decision was kind of a safety one. The real name, the one inside the `strong` tag, is red from the very first paint. It pulls its color from a token:

```css
--name-accent: #9d2e1c;              /* light mode */
--name-accent: oklch(0.75 0.13 32);  /* dark mode */
```

So if the animation never runs, or the CSS for it breaks, you still get a red name and the page looks finished. The effect is a layer on top of that. I never animate the real text.

The layer is a second copy of my name, in ink, sitting right on top of the red one:

```html
<strong class="portfolio-hero__name">
  Jack Cao
  <span class="portfolio-hero__name-ink" aria-hidden="true">Jack Cao</span>
</strong>
```

The animation just wipes that ink copy away.

## A wipe instead of a fade

My first idea was to fade the ink layer out. The problem with fading two colors is the middle. Halfway through, dark ink over red turns into this muddy brown that doesn't belong to either theme, and it made the whole heading look dirty for a split second.

A clip doesn't have that problem. Every pixel is either ink or red, and the edge between them slides across the word kind of like a pen stroke.

```css
@keyframes portfolio-name-reveal {
  from { clip-path: inset(0 0 0 0); }
  to { clip-path: inset(0 0 0 100%); }
}
```

`inset(0 0 0 100%)` pushes the left edge of the clip all the way to the right. So the ink layer gets eaten from the left side, and the red shows up in the same order you read it. The letters themselves never move, which means nothing shifts on the line.

## Making the copy invisible to everything else

Putting a second copy of my name on the page causes a few problems that I had to clean up.

A screen reader would read it as "Jack Cao Jack Cao." `aria-hidden="true"` on the copy takes it out of the accessibility tree.

If you selected the heading and copied it, you'd also get my name twice. `user-select: none` keeps the copy out of the selection, and `pointer-events: none` lets clicks go through to the real text underneath.

The copy also needs to sit exactly on top of the name. The `strong` gets `position: relative` and `display: inline-block`, and the copy is absolutely positioned at `inset: 0` inside it. I also added `white-space: nowrap`, so the name can never break across two lines. A clip crossing a line break would look pretty weird.

## Two media queries that turn it off

The ink copy is `display: none` by default. It only shows up inside this block:

```css
@media (prefers-reduced-motion: no-preference) and (forced-colors: none) {
  .portfolio-hero__name-ink {
    position: absolute;
    inset: 0;
    display: block;
    color: var(--portfolio-ink);
    pointer-events: none;
    user-select: none;
    animation: portfolio-name-reveal 700ms var(--ease-out) 600ms both;
  }
}
```

I wrote it as opt-in on purpose. If you have reduced motion turned on, you just get the red name, no wipe. And because the query asks for `no-preference` instead of checking for `reduce`, a browser that doesn't understand the query at all also lands on the static version.

Forced colors was the one I almost missed. That's the mode Windows High Contrast uses, where the system swaps out your colors for its own. In that mode my ink and my red both turn into the same system text color. The animation would be wiping one black over another black, so you'd see nothing, and there'd still be an extra layer of text sitting on the page for no reason. So I hide it there too.

## How I'd check your own text effect

If you're building something like this, these are the things I'd run through before shipping it:

1. Turn the animation off and make sure the page still looks finished.
2. Run a screen reader over it and listen for anything read twice.
3. Select the text, copy it, and paste it somewhere.
4. Open DevTools, go to the Rendering panel, and turn on reduced motion and forced colors one at a time.
